# EasyElevator

Minecraft **1.21.1** · Fabric Loader **0.19.2** · Fabric API **0.116.17+1.21.1** · Java **21**。

当前模组版本 **1.5.6**。五个组件：电梯轨道、楼层电梯门，以及三种电梯轿厢（普通／高速／观光）。三种轿厢共用同一个父类 `entity/AbstractCabinEntity`，彼此只差**速度**与**外观**两项，运动、门联锁、载客与存档完全同一份实现。当前采用无图案白模，声音默认静音，便于后续替换。

## 搭建和使用

1. 从创造模式「简易电梯」物品栏取出五个组件，或使用配方合成。
2. 垂直放置一列连续轨道。第一块轨道朝向放置者，后续上下延伸会继承方向。**轨道朝向是轿厢所在方向，也是轿厢门朝向**。
3. 在轨道朝向前方 **3 格**、同一 Y 高度，放置电梯门的**底部中心**。一件物品自动生成 **3 格宽、3 格高**的整扇门，预留完整空间。距离按方块坐标计算，不是中间空出3格。每扇完整门对应一个站点，按高度排序。
4. 手持任意一种「电梯轿厢」，右键任意一块轨道。轿厢中心位于该轨道朝向的前方 2 格；底部 Y 与被点击轨道相同。预留 **3×3 的井道、3 格轿厢高度**，整个运行区间清空。每段连续线路只能放置一个轿厢（三种型号一起计数：同一条线路上再放第二种会被拒绝）。
5. **右键楼层电梯门**：不再直接呼叫，而是弹出**厅外呼叫面板**——**同尺寸的小方块**竖排成一列：**▲（上行）**、**▼（下行）**、**×（关闭）**（悬停显示"关闭"）。**端站只显示有意义的方向**：最底层下面没有站点，只显示 ▲；最顶层上面没有站点，只显示 ▼；中间层两个都在。按下方向键后服务端登记这条带方向的呼叫，按钮随即**变红**并一直亮着，直到轿厢真的到站开门那一刻才熄灭（关掉面板再打开也能看到它仍然红着）。没有轿厢到达这一层时，楼层门保持关闭，具有实际碰撞；到站并开始开门后开放，轿厢门关闭完毕、运行前重新锁闭。
6. **潜行右键楼层电梯门**：把这一站设为整条线路的**基准层（1 层）**——它下方的站点依次显示 **B1、B2……**，上方的依次显示 **2、3……**。轿厢内的选站面板、轿厢内面板与所有楼层门框顶部的层号会立刻按新编号显示。默认（没有设置基准层时）仍然是最底层 = 1 层；把基准门拆掉也会回到默认编号。
7. 进入轿厢后右键打开选站面板：站点排成一整块方形数字按键（模拟真实电梯面板），编号按高度从 1 起、**最底层为 1 层**（设了基准层后按第 6 条编号）；按钮从**右下角**起步，先**从右往左**、再**从下往上**排列，列数自动选成尽量长方形，站点较多时用底部的 `<` `>` 翻页。悬停显示站点与高度；**轿厢当前停靠层**的按键为绿色描边，**已加入停靠计划**（正在前往或已排队）的按键为红色描边——绿色与开门键都只在轿厢**停稳**后出现，运行时经过楼层不会闪一下。面板自上而下分成**表头条**（标题 + 左上角楼层指示牌 + 右侧"高度 / 页数"）、**按键区**（比面板更暗的凹底托住整块数字键）、**页脚条**（翻页 / 开门 / 关门 / 完成），三条色带之间用 1 像素分隔线断开；面板底**不透明**，井道里的红字不会从底下透出来。楼层指示牌为**深底红字、放大 2 倍、只显示层号本身**如 `3` / `B1`，不再写"第 n 层"，与右侧的"高度"行、"n 个站点"行并排，每经过或到达一层更新一次；同一个层号还用红字显示在**楼层门框顶部**与**轿厢内的模拟面板**上——轿厢面板是两行（**第一行是闪烁的方向箭头、第二行是到达层数**），门框则是横向一行（左边箭头、右边层数，整组居中，例如"▲ 3"）；箭头只有**正在运行时**才出现——**上行 ▲、下行 ▼**，**停靠（含开门、暂停）时留空**，并且**一亮一灭地闪烁**（亮 0.5 秒 / 灭 0.5 秒，门框与轿厢面板同相）。运行状态由已同步的相位与目的站推导，不需要额外同步字段。底部另有**开门 / 关门**键：**开门**会把**正在关闭的门反向重新打开**（中断关门）、也能把已关好停在本层的门重新打开，门已全开时相当于按住开门键延长停留——它**只操作门，不会把本层排进呼叫队列**，因此不会出现"先开走、之后再回来"；**关门**会立刻结束停留并关门，队列里还有目的站时随后出发。两个键都只在轿厢停稳在某一层时有效（运行途中经过楼层时按不动）。面板取消背景模糊，使用轻微暗色遮罩，游戏画面与文字保持清晰。选择后由服务端重新检查整扇门及线路，随后入队。
8. 无人乘坐且门完全打开时，在轿厢外**空手潜行右键**回收轿厢。生存模式返还物品。生存模式拆掉楼层门任意一部分，整扇门一起移除，只返还一个门物品。

### 呼叫调度：方向、顺路与停靠顺序

- **轿厢内选站**是"目的层"，没有方向，任何行程方向都能服务；**厅外呼叫**带方向，只有**正在按该方向运行**的轿厢才会顺路接走（现实电梯的集选控制）。例如车在 1 层上行时，5 层的"上行"与车内的 8 层会依次停靠，而 8 层的"下行"要等车到顶掉头下行时才接。
- 停靠按**运行方向上的位置顺序**，不是按键先后：上行途中不会越过同一方向的楼层再去更远的那层；**运行途中新插入的同方向更近请求会被立刻插到前面**（正驶向 10 层时有人在 5 层按了上行，轿厢会先在 5 层停，而不是径直开过）——插入时队列即按服务方向重排，面板上的"停靠计划"顺序就是实际停站顺序。请求全部完成后轿厢停车待命，服务方向复位为空闲。
- 反方向的孤立呼叫（例如车在 1 层、8 层按下行）也会被服务：轿厢会空车上去接他——不会因为方向不一致而永远等不到车；到站开门只清掉**与本次服务方向一致**的那条呼叫（按钮随之熄灭）。
- **服务方向 = 轿厢实际要开的方向**（不是按钮的方向）：空车去接反方向呼叫时，沿途凡与轿厢同向的厅外呼叫都会被顺路接走。
- **方向记忆**：轿厢停车开门等乘客时会**保留刚才的服务方向**——被下行呼叫叫到 5 层、进厢后按 6 层、而楼下还有呼叫时，轿厢先把这一趟跑完（下到 1 层接人）再上行去 6 层；**只有当前方向的前方再也没有请求**时才会掉头（五层以下无人呼叫时才直接上行）。例如车在 10 层、底层按"上行"、二层按"下行"：轿厢向下开，途中先在二层停下接"下行"的乘客，再到底层——不会一路开到底层再折返二层（顶端站同理）。
- **同一层的上行与下行呼叫各自独立**：到站开门只熄灭"这一趟服务方向"的按钮。所以 2 层同时按了上行和下行时，上行到达只熄上行那盏灯，**下行那条会一直亮着**，等轿厢回头下行再来接（测试用例 ⑱）。
- **先来先服务**：轿厢空闲时被派往的目的地永远是**最早登记的那条呼叫**，不是最近的那条——1 层先按"上行"、2 层随后也按"上行"时，轿厢先下到 1 层，再顺路上来接 2 层；后登记的**反方向**呼叫永远不会半路抢走目的地（运行途中只有**同方向**的呼叫能被顺路接走）。顶端站镜像同理：顶层先按"下行"、中间层随后也按"下行"时，先到顶层再顺路下行接中间层。
- 厅外呼叫随轿厢一起存档（站点坐标 + 方向 + 当前服务方向），读档后继续服务；楼层门被拆时该站的呼叫自动取消。

### 楼层编号：基准层与地下层

- 默认编号：站点按高度升序，**最底层 = 1 层**，向上 2、3……
- **潜行右键**任意一扇楼层门，即把它设为**基准层 = 1 层**：比它低的依次显示 **B1、B2……**（内部用负数表示），比它高的依次显示 **2、3……**。设置写在那一扇门的方块实体里，随区块存档；一条线路最多一扇门带这个标记，再次潜行右键别的门就会改基准。
- 三处显示同源：轿厢内选站面板的按钮编号、轿厢内面板的层号、所有楼层门框顶部的层号，全部来自同一个 `logic/FloorIndicator`，因此不会出现"面板显示 B1、门框显示 0"这类分叉。

### 三种轿厢

| 型号（物品／实体 ID） | 速度 | 外观 | 与普通型的差别 |
| --- | --- | --- | --- |
| 电梯轿厢 `easyelevator:cabin` | 4 格/秒 | 白色封闭轿厢 | 默认型号；旧存档里的轿厢就是它 |
| 高速电梯轿厢 `easyelevator:high_speed_cabin` | **10 格/秒**（2.5 倍） | **与普通型逐面相同** | 只有速度：门时序、到站精度、防夹与联锁一个字都没改 |
| 观光电梯轿厢 `easyelevator:observation_cabin` | 4 格/秒 | 四面墙改玻璃，保留**四个支撑边**（角柱）与地板、顶板 | 只有外观：碰撞、井道、载客、防夹与联锁与普通型逐条相同 |

- 三者的井道要求都是 **3×3×3**、都占 3 格高、都掉回**本型号**物品（空手潜行右键回收），因此换型号不需要改建井道或楼层门。
- 高速型按 **2.5 倍**步长运行（0.50 格/刻），单刻位移仍小于 1 格，所以整格站点不会被跳过，最后一步照旧精确吸附到站点高度；开关门与开门停留时间**不会**同比缩短，速度快只体现在运行段。
- 观光型的玻璃是**纯客户端绘制**：四个角柱、地板、顶板与操作面板保持不透明，左右侧墙、后墙与两扇门各是一张半透明单面玻璃（正反都可见）；碰撞外壳仍按 0.2 格厚实心墙生成，所以玻璃墙照样挡住乘客，井道与站点无需任何改动。玻璃走一个"只写颜色、不写深度"的专用渲染层，因此**不会把楼层门挡住**（原版渲染顺序是实体在前、方块实体在后，玻璃若写深度就会把后画的楼层门整片剔掉）。
- 实现上三种轿厢继承同一个父类：`entity/AbstractCabinEntity` 承载全部逻辑，`CabinEntity` / `HighSpeedCabinEntity` / `ObservationCabinEntity` 每个只有十几行（构造时传入速度、覆写回收物品与是否玻璃）。
- 高速型**外观与普通型完全一致**（同一个渲染分支、同一套几何），因此没法"看外观认速度"——只能从到站时间察觉。

### 一个具体示例

轨道放在 `(0, 64..80, 0)`，全部朝 `south`。在 `(0,64,3)`、`(0,72,3)`、`(0,80,3)` 放置楼层门底部中心，方向由轨道自动确定。

右键 Y=64 的轨道生成轿厢后，轿厢中心为 `(0.5,64,2.5)`，占地为 X=-1..1、Z=1..3，门朝南，门外走廊在 Z≥4。地板表面是 Y=64.2；楼层走廊表面可用 Y=64，0.2 格的门槛可正常走上。其他楼层同理。

每扇门占 X=-1..1、Z=3、Y=楼层高度..高度+2，门面位于这些方块朝走廊一侧，与轿厢正面的门口对齐。轨道 (0,64,0) → 轿厢中心 (0.5,64,2.5) → 门底部中心块 (0,64,3) → 走廊 Z≥4。

轿厢正面的模型和碰撞已内收0.2格，楼层门与轿厢门之间留有0.0125格间隙，避免门和门框重叠闪烁。上述轨道、楼层门位置和井道预留空间仍适用。

当前是**直上直下轨道**，横向相邻轨道是独立线路，不支持转弯、斜轨或分岔。每条线路同一高度只能设置一扇正面的门。

### 从旧版升级

原按钮的注册 ID `easyelevator:call_button` 保留，但现在显示并放置为「电梯门」，已有物品不会丢失。**已放置的旧按钮需拆下，按距轨道3格的新位置重放**；不自动覆盖周围建筑生成大门。旧按钮位置不再是有效站点。门的9个组成方块只计为一个站点。

已有存档里的轿厢不需要重建：它就是**普通电梯轿厢**（注册 ID 与行为都没变）。新增的高速／观光轿厢是两件新物品（合成或用创造物品栏取出），各自的实体 ID 也是新的，因此不会与旧存档里的实体冲突；同一条线路上仍然只能有一台轿厢（三种型号一起计数）。

### 行为

- 普通与观光轿厢速度 **4 格/秒**，高速轿厢 **10 格/秒**（2.5 倍）；开关门各 1 秒，开门停留至少 2 秒；无新请求时保持开门。提高速度只缩短运行段，不会缩短开关门与停留时间。
- 楼层门与轿厢门是同一套动画：门框常驻，两扇门扇随进度向两侧收拢滑入门框，不再瞬间变成一堵墙。
- 到站误差容限 1e-7 格，最后一步精确对齐站点；double 运动样本和约100 ms显示缓冲，让轿厢和本地乘客镜头逐帧插值。
- 请求按**运行方向上的位置顺序**停靠（不是按键先后）：同一方向上的楼层依次服务，相同站点重复请求合并；厅外呼叫按方向只被顺路的那一趟接走，反方向的孤立呼叫也会被服务（空车去接）。轿厢内选站与厅外呼叫合计最多等待 128 条。
- 门未完全关闭不能移动；门口有生物会重新开门并保留原请求。
- 乘客站在空心轿厢内随轿厢移动，不要求骑乘；服务端同步位置并清除下落伤害。
- 断轨、轨道朝向不一致、运行区域有实体/方块障碍、区块未加载时停止；恢复后继续原行程。
- 运行中拆除目的站电梯门会暂停并取消该目的站；其他有效请求可以继续，或从轿厢重新选站。避免在半空开门。
- 轿厢、目标、队列和门进度保存进世界。重载后先检查线路再恢复运行。
- 不主动加载区块；线路及井道需要在已加载范围内。多人服务器和客户端都要安装模组与 Fabric API。

## 替换模型与音效

详细接口见 [docs/ASSET_INTEGRATION.md](docs/ASSET_INTEGRATION.md)。

- 轨道模型：`assets/easyelevator/models/block/elevator_rail.json`
- 楼层门**门框**模型（常驻）：`assets/easyelevator/models/block/landing_door_frame_*.json`；门物品图标：同目录 `call_button.json`
- 楼层门**门扇**：`src/client/java/org/DJB/easyelevator/client/LandingDoorRenderer.java`，几何在 `block/LandingDoorGeometry.java`
- 轿厢及双扇门：`src/client/java/org/DJB/easyelevator/client/CabinRenderer.java`（普通与高速型共用不透明白模；观光型的玻璃面色与厚度也在同一个类里，见 `GLASS_COLOR` / `drawObservation`）
- 运行/到站/开门/关门音效：`assets/easyelevator/sounds.json`
- 门动画：轿厢门 `CabinEntity.doorProgress(tickDelta)`；楼层门门扇 `LandingDoorBlockEntity.openProgress(tickDelta)`，逐刻等于在站轿厢的门进度，0 关闭、1 打开。
- 服务端扩展事件：`ElevatorEvents.PHASE_CHANGED`、`ElevatorEvents.ARRIVED`。

## 构建

先将 `JAVA_HOME` 指向 **JDK 21**，然后在项目目录执行：

```powershell
.\gradlew.bat build
```

成品在 `build/libs/easyelevator-1.5.6.jar`；带 `-sources` 后缀的是源码包，不放入 mods 文件夹。

完整说明见 [工程构建与打包说明书](docs/BUILD_AND_PACKAGING.md)；所有运行、精度、动画、尺寸、面板和音效参数见 [电梯参数手册](docs/PARAMETERS.md)。

本机快捷构建和两种打包：

```powershell
.\tools\build.ps1 -Jdk 'E:\workspace\JAVA\JAVA21' -Task build
.\tools\build.ps1 -Jdk 'E:\workspace\JAVA\JAVA21' -Task packageRelease
.\tools\build.ps1 -Jdk 'E:\workspace\JAVA\JAVA21' -Task packageProject
```

开发启动：`./gradlew.bat runClient`。可以脱离游戏单独跑的检查：

```powershell
.\tools\test-logic.ps1 -Jdk '你的 JDK 21 目录'   # 状态机与运动时间线
.\gradlew.bat geometryTest                       # 楼层门门框/门扇几何（改门模型或门尺寸后跑）
```

服务端 GameTest 在当前工程里没有注册成 gradle 任务，用 IDEA 运行配置 **Gametest Minecraft Game Test** 运行；详见 [验收清单](docs/TESTING.md)。

## 文件组织

| 目录/类 | 职责 |
| --- | --- |
| `block/`、`item/` | 轨道、3×3楼层门及呼叫联锁、轿厢放置和回收 |
| `logic/ElevatorLine` | 轨道连续性、站点扫描、单线路单轿厢 |
| `logic/ElevatorController` | 独立状态机、门联锁、请求队列 |
| `entity/AbstractCabinEntity` | 三种轿厢的共同父类：实际位移、乘客、障碍检测、存档、同步 |
| `entity/CabinEntity`、`HighSpeedCabinEntity`、`ObservationCabinEntity` | 普通／高速（2.5 倍速）／观光（玻璃墙）三个型号，各自只声明速度、回收物品与外观开关 |
| `mixin/EntityViewMixin` | 空心轿厢地板、侧壁、门的实体碰撞 |
| `network/` | 面板数据和选站请求；服务端验证 |
